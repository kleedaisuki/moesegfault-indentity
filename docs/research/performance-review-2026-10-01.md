# Independent performance-change review

Date: 2026-10-01. Scope: the working-tree performance changes, not a production deployment. This review does not modify production code. Relevant contract: ADR-0002 keeps D1 authoritative, sensitive session/CSRF state in memory, and HTTP shapes stable.

## Backend session activity gate

Reviewed `repository.rs::current_session`, `account_repository.rs::current_session`, `repository.rs::touch_session`, the session projection and callers. No substantive correctness/security defect found in the inspected change.

- Both authentication lookups retain FirstPrimary and the existing principal-active, revoked, idle-expiry and absolute-expiry predicates. There is no authentication cache or deferred renewal.
- The SELECT additionally reads authoritative `last_seen_at`. Internal `SessionActivity<T>` unwraps back to the old return projection; the timestamp does not alter the HTTP shape.
- For ordinary Unix-second inputs, `last_seen_at <= now.saturating_sub(300)` matches the original SQL `last_seen_at<=?2-300` renewal gate. Only formerly no-op remote UPDATE calls are skipped.
- A due renewal still awaits the original conditional UPDATE. Its expiry/revocation guards and absolute-expiry clamp are unchanged. Concurrent renewal after the SELECT can still make the UPDATE a no-op, as before. Concurrent revocation after the SELECT is an existing time-of-check/use window, not introduced by this gate; mutation-specific authority predicates must remain intact.
- Mechanism-level gain: one fewer awaited D1 operation per authenticated lookup whose last activity is younger than 300 seconds. This is not a measured production response-time claim; anonymous failures are unaffected.

Validation complete according to the implementation handoff and inspected artifacts: real release-Wasm account `/v1/me` uses three calls when fresh and four when due; generic `/v1/browser-context` uses one/two, with successful session decoding. `cargo test --workspace --all-features --locked` passed 14 domain tests, 88 Worker tests and one doctest (two existing Worker doctests ignored). Worker Clippy with warnings denied, formatting and release Wasm build passed. The reviewer reused these results rather than duplicating execution. See [backend investigation](backend-performance-2026-10-01.md) for raw artifact paths and environment.

## Frontend changes

Reviewed both `apps/*/public/_headers` changes and their new cache-header configuration tests. No substantive defect found in this inspected slice. All broad security headers remain unchanged. Immutable caching now targets only current Vite content-hashed entry JavaScript/CSS names; mutable public SVGs no longer inherit the Login `/assets/*` year-long cache policy. Header removal before addition matches the documented mechanism for clearing a pervasive header. String assertions lock down source configuration but do not demonstrate the deployed platform's response headers. The implementation agent subsequently supplied `.temp/frontend-cache-runtime.json`: 11 local Wrangler path cases with 200 and explicit conditional 304 preserve security headers; all four hashed bundles carry exactly the desired immutable policy, while HTML/unversioned SVG policies remain unchanged. The reviewer inspected the artifact without repeating checks. Login 56 tests, Account 50 tests and both TypeScript/Vite builds are reported passed; see [frontend investigation](frontend-performance-2026-10-01.md). Cold first visits are not accelerated by browser cache reuse; repeat loads are the intended beneficiaries. No deployment or warm-browser timing was performed.

## Backend runtime fixture and CI integration

Reviewed `crates/identity-worker/tests/session-performance.mjs` and the added npm/CI entries. Fixtures live under repository `.temp`, use local Miniflare/workerd and the release Wasm, and do not mutate production. Request-local D1 instrumentation counts calls, including statements made through `withSession`, rather than treating changed-row counts as a request count. The package CI job restores the tested release artifact before invoking this harness. Semantic cases cover account/generic fresh and due reads, expiry, revocation, inactive principals and absolute-expiry clamping. Concurrent requests check successful responses and clamp preservation, not a deterministically forced competing-read interleaving. The existing SQL CAS remains the source of the concurrent-update safety argument.

Injected 20/80 ms delay per D1 operation is an explicit model, not a measured D1 latency. Alternating before/after request order and five warmups reduce order/startup bias; 25 samples permit a descriptive p95 but not stable production tail inference. The CLI uses a baseline artifact only when explicitly supplied; normal CI verifies the current request budget without reconstructing the old Worker or running the optional timing loops. The inspected baseline report shows median local whole-request times of 10.70/8.96 ms (no injection), 122.41/91.14 ms (20 ms injection), and 363.46/273.13 ms (80 ms injection), before/after respectively. Shared-machine concurrent security validation and Windows timers are explicit noise sources. These are sensitivity experiments confirming removed serial work, not an end-user speedup estimate.

The optional unknown-identifier password probe produced 12 measured samples, median 39.27 ms and p95 43.50 ms, exercising dummy Argon2 and denial locally. This is evidence against a multi-second local dummy-hash bottleneck, not a successful-login or production CPU benchmark. The independent validator also passed real Worker request-boundary and password-authority suites, including stale-proof denial, cookie rotation, revoked-old-session denial and nonreplay of secrets; see [validation](performance-validation-2026-10-01.md).

## Anonymous HTTP measurement tooling

Reviewed `scripts/measure-http-latency.mjs` and `scripts/tests/http-latency.mjs`. No substantive defect found. The CLI bounds targets and samples before requests; seven fixed anonymous GETs have 5-second connect, 12-second curl transfer and 15-second process limits, a 1 MiB body cap, no redirects, no supplied cookies and no retries. curl configuration-file loading is disabled. Output includes only an explicit response-header allowlist, not bodies, Set-Cookie or proxy URLs. Summaries exclude failed timing samples but report failures, and avoid tail-percentile claims for tiny samples. Root reports five offline tests and seven-endpoint live smoke passed; this reviewer did not repeat them.

Each sample uses a fresh curl process: connection setup is measured, browser warm connections and rendering are not. `--direct` disables explicit proxy use but does not bypass VPN/TUN routing. European edge identifiers in both modes cannot independently identify a proxy as the cause. Three samples per endpoint are descriptive diagnostics, not statistically stable production latency estimates.

## Evidence interpretation and external references

- [Cloudflare D1 sessions](https://developers.cloudflare.com/d1/worker-api/d1-database/) distinguishes primary-first reads from replica-first reads. The optimization retains the security-sensitive primary-first lookup rather than weakening freshness for latency.
- [Cloudflare Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/) recommends explicit promise lifecycle management. Renewal still uses an awaited operation; indiscriminately moving a security/session-lifetime transition into background work would need a separate contract and failure analysis.
- [Cloudflare Workers Static Assets headers](https://developers.cloudflare.com/workers/static-assets/headers/) and [Pages headers](https://developers.cloudflare.com/pages/configuration/headers/) document multi-rule header inheritance, comma joining of duplicate headers, `! Header` removal and single-splat matching. Narrow hashed-bundle rules match these semantics; the project's relevant local runtime is Workers Static Assets, not a Pages Functions response path.
- [CRISP, USENIX ATC 2022](https://www.usenix.org/conference/atc22/presentation/zhang-zhizhou) motivates critical-path analysis across RPC traces. It supports counting removed serialized work, not assigning a speedup from static inspection.
- [Panorama, USENIX ATC 2024](https://www.usenix.org/conference/atc24/presentation/li-geng) demonstrates the importance of actual end-to-end network paths in global interactive services. Its real-time overlay results do not transfer quantitatively to this SPA. Proxy/direct/local traces and a mainland-China user path must be distinguished before attributing perceived latency to code.

Review limits: no authenticated production traffic, production mutation, deployed before/after test or end-user device trace. Local runtime measurements cannot establish mainland-China production p95/p99 latency.

## Final assessment

No substantive defect found in the reviewed production changes, diagnostic tool, local harness or npm/CI integration. The changes improve demonstrated cache policy and remove a provably unnecessary session operation without weakening public contracts or authority freshness. Existing general revocation read/write ordering is not solved or worsened. The strongest benefit statement is conditional: each fresh authenticated lookup skips one operation; whether such lookups dominate actual production traffic has not been measured. Remaining perceived first-load, scroll and input latency needs representative user-path/browser evidence, not speculative CSS rewrites or security-parameter reductions. Remote CI execution and postdeployment verification remain outside this review.
